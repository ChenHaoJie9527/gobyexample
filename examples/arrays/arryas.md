# arrays 进阶教程

这个示例表面上是在讲 Go 的数组，但如果只把它理解成“固定长度的一组值”，那还远远不够。

真正值得学的是下面这几件事：

1. 数组在 Go 里是一个独立类型，不只是“切片的底层实现”
2. 数组长度属于类型的一部分，这会直接影响赋值、传参和比较
3. Go 日常开发里，数组能用，但绝大多数场景更常用的是切片
4. 只有理解“数组是值类型”这一点，很多行为才不会看起来反直觉

如果你把这些点理解透，后面学切片、`range`、`copy`、函数传参时会顺很多。

## 先看 `arrays.go` 想表达什么

`[arrays.go](/Users/momotom/gobyexample/examples/arrays/arrays.go)` 主要演示了这几件事：

```go
var a [5]int
a[4] = 100

b := [5]int{1, 2, 3, 4, 5}

var twoD [2][3]int
```

它分别在讲：

1. 如何声明一个固定长度的数组
2. 如何按索引读写元素
3. 如何用字面量初始化数组
4. 如何声明多维数组
5. `len` 如何获取数组长度

这些都是基础语法，但 Go 的重点并不只是“会写”，而是理解数组的类型语义。

## 一、什么是数组

在 Go 中，数组是：

- 同一种元素类型组成的定长序列
- 长度固定
- 长度属于类型本身
- 值类型

例如：

```go
var a [5]int
var b [5]int
var c [4]int
```

这里：

- `a` 和 `b` 的类型相同，都是 `[5]int`
- `c` 的类型是 `[4]int`
- `[5]int` 和 `[4]int` 是两种不同类型

这一点非常关键。很多语言里，数组更像“容器对象”；但在 Go 里，数组更像一个被完整定义好的值。

## 二、为什么说“长度是类型的一部分”

这是 Go 数组最核心的特征。

看这个例子：

```go
var a [3]int
var b [4]int

// a = b // 编译错误
```

虽然它们的元素都是 `int`，但：

- `a` 的类型是 `[3]int`
- `b` 的类型是 `[4]int`

长度不同，所以类型不同，不能直接赋值，也不能当成同一种参数传来传去。

这意味着数组特别适合表达“长度就是业务约束的一部分”的场景，例如：

- 坐标：`[3]float64`
- RGB 颜色：`[3]uint8`
- IPv4 地址：`[4]byte`
- SHA256 摘要：`[32]byte`

这些场景里，“长度固定”不是偶然，而是数据定义的一部分。

## 三、数组是值类型，不是引用类型

这是最容易踩坑、也最值得记住的一点。

### 1. 赋值会复制整个数组

```go
a := [3]int{1, 2, 3}
b := a
b[0] = 100

fmt.Println(a) // [1 2 3]
fmt.Println(b) // [100 2 3]
```

这里 `b := a` 不是共享底层数据，而是完整复制了一份数组值。

### 2. 函数传参默认也会复制整个数组

```go
func reset(a [3]int) {
	a[0] = 0
}
```

调用 `reset(x)` 时，传进去的是副本，函数内修改不会影响外部变量。

如果你确实要修改原数组，常见写法有两种：

```go
func reset(a *[3]int) {
	a[0] = 0
}
```

或者更主流一些，直接改用切片：

```go
func reset(s []int) {
	s[0] = 0
}
```

从 Effective Go 的风格看，除非“固定长度”本身就是 API 语义，否则大多数函数参数更适合用切片而不是数组。

## 四、数组的零值和初始化方式

示例里的这行代码：

```go
var a [5]int
```

说明了两个事实：

1. 数组创建后，每个元素都会被自动初始化为对应类型的零值
2. `int` 的零值是 `0`

所以输出会是：

```go
[0 0 0 0 0]
```

如果元素类型换成别的类型，对应零值也会不同：

```go
var names [2]string   // ["", ""]
var flags [3]bool     // [false false false]
var ptrs [2]*int      // [nil nil]
```

常见初始化方式有几种。

### 1. 指定长度的字面量初始化

```go
b := [5]int{1, 2, 3, 4, 5}
```

### 2. 让编译器推导长度

```go
nums := [...]int{1, 2, 3, 4}
```

这时 `nums` 的类型会被推导成 `[4]int`。

这种写法在“我知道元素列表，但不想手算长度”时很方便。

### 3. 按索引初始化

```go
scores := [5]int{0: 100, 3: 88}
```

结果是：

```go
[100 0 0 88 0]
```

这种写法适合稀疏初始化，也更利于阅读。

## 五、如何访问和遍历数组

### 1. 按索引访问

示例里已经演示了：

```go
a[4] = 100
fmt.Println(a[4])
```

需要注意：

- 下标从 `0` 开始
- 越界会直接 `panic`

例如：

```go
_ = a[5]
```

如果 `a` 是 `[5]int`，那合法索引只有 `0` 到 `4`。

### 2. 用传统 `for` 遍历

```go
for i := 0; i < len(a); i++ {
	fmt.Println(i, a[i])
}
```

这种方式适合：

- 需要显式控制索引
- 需要前后元素对比
- 需要跳步、倒序、局部遍历

### 3. 用 `range` 遍历

```go
for i, v := range a {
	fmt.Println(i, v)
}
```

这是更常见的 Go 写法，可读性通常更好。

如果只关心值：

```go
for _, v := range a {
	fmt.Println(v)
}
```

如果只关心索引：

```go
for i := range a {
	fmt.Println(i)
}
```

## 六、`range` 遍历数组时要特别注意什么

数组上的 `range` 有一个很容易被忽略的点：

- 对数组做 `range` 时，`range` 使用的是数组值的一个副本

这在大数组或边遍历边修改时尤其需要小心。

例如：

```go
a := [3]int{1, 2, 3}

for i, v := range a {
	if i == 0 {
		a[1] = 100
	}
	fmt.Println(i, v)
}
```

输出里第二次拿到的 `v` 仍然可能是旧值，因为 `range` 拿的是开始遍历时的副本。

如果你希望每次都读到当前数组的最新值，更稳妥的方式是使用索引循环：

```go
for i := 0; i < len(a); i++ {
	fmt.Println(i, a[i])
}
```

这类细节在切片上也常被讨论，但数组由于值语义更容易让人误判。

## 七、多维数组怎么理解

示例里的这段代码：

```go
var twoD [2][3]int
```

表示的是：

- 有 2 个元素
- 每个元素本身又是一个 `[3]int`

所以它的类型不是“二维魔法结构”，而是：

- 一个长度为 2 的数组
- 里面每个元素都是长度为 3 的数组

你也可以这样理解：

```go
twoD[0] // 类型是 [3]int
twoD[1] // 类型也是 [3]int
```

这种结构特别适合规则矩阵、棋盘、固定维度表格等数据。

如果内层长度可能不一致，那通常应该使用切片的切片，而不是多维数组。

## 八、数组和切片到底是什么关系

这是学习 Go 序列类型时最重要的分界线。

### 数组

- 长度固定
- 类型包含长度
- 值语义
- 赋值和传参会复制整个数组

### 切片

- 长度可变
- 类型只关心元素类型
- 本质上是对底层数组的一层描述
- 更适合日常开发中的集合操作

例如：

```go
arr := [5]int{1, 2, 3, 4, 5}
s := arr[1:4]
```

这里：

- `arr` 是数组
- `s` 是切片
- `s` 指向 `arr` 的一段区间

修改切片元素会影响底层数组：

```go
s[0] = 100
fmt.Println(arr) // [1 100 3 4 5]
```

所以从主流 Go 实践看：

- 需要固定长度语义时，用数组
- 需要灵活处理一组元素时，用切片

绝大多数业务代码都更常见 `[]T`，而不是 `[N]T`。

## 九、主流开发里数组通常怎么用

在真实项目中，数组不是完全不用，但使用场景比切片窄得多。

更常见的数组使用方式有这些。

### 1. 表达固定长度的数据

```go
type RGB [3]uint8
type Vec3 [3]float64
```

这里数组的价值在于：

- 长度固定
- 类型清晰
- 不容易误传成别的长度

### 2. 处理固定大小的二进制数据

标准库里就很常见这种模式：

```go
var sum [32]byte
```

例如哈希摘要、协议头、固定长度标识符。

### 3. 作为底层存储，再切出切片使用

```go
buf := [1024]byte{}
s := buf[:0]
```

这种写法常见于：

- 性能敏感代码
- 需要预分配固定缓冲区
- 希望减少额外分配

它的思路是：

- 用数组承载实际存储
- 用切片提供更灵活的操作接口

这比“全程直接操作数组”更符合 Go 的日常编码习惯。

## 十、哪些场景不建议硬用数组

下面这些情况，一般优先考虑切片：

- 元素数量运行时才能确定
- 需要 `append`
- 需要把数据传给大量标准库或第三方库 API
- 需要更灵活的切片、复制、拼接操作

例如这类接口：

```go
func process(items []int) {}
```

通常比：

```go
func process(items [8]int) {}
```

更通用，也更符合多数 Go 开发者预期。

如果你发现自己只是“想放一串值”，但并不依赖固定长度的语义，那通常应该先想切片。

## 十一、常见坑

数组这个主题不难，但坑很典型。

### 1. 误以为数组和切片差不多

它们长得像，但类型语义差别很大。

```go
[3]int
[]int
```

这不是同一种东西，不能混用。

### 2. 误以为传数组进函数会原地修改

```go
func change(a [3]int) {
	a[0] = 99
}
```

这里修改的是副本，不是原值。

### 3. 误以为不同长度的数组可以互相赋值

```go
var a [3]int
var b [4]int

// a = b // 不行
```

长度不同，类型就不同。

### 4. 对数组 `range` 时忽略“副本语义”

如果边遍历边修改，结果可能和你直觉不一样。

需要实时读取最新值时，优先考虑索引循环。

### 5. 把大数组频繁按值传递

数组是值类型，传参和赋值会复制全部元素。

如果数组很大，这会带来额外开销。常见优化方式：

- 改成传切片
- 或者传数组指针 `*[N]T`

不过从 API 设计上说，很多时候“改成切片”会更自然。

### 6. 越界访问

Go 不会像某些语言那样悄悄返回空值，数组越界会直接触发运行时错误。

这很好，因为它能尽早暴露 bug，但也要求你特别注意边界条件。

## 十二、一个更符合主流 Go 风格的理解方式

学习数组时，建议用下面这个心智模型：

1. 数组是“固定长度的值”
2. 切片是“对一段序列的灵活视图”
3. 业务开发默认先考虑切片
4. 只有当“固定长度”本身有意义时，数组才是更好的建模方式

这比死记语法更重要。

看完 `[arrays.go](/Users/momotom/gobyexample/examples/arrays/arrays.go)`，最值得带走的不是“怎么写 `[5]int`”，而是下面这些结论：

1. Go 数组是定长、同类型、值语义的数据结构
2. 数组长度属于类型的一部分
3. 数组赋值和传参默认复制整个值
4. 多维数组本质上是“数组的数组”
5. 日常开发里数组能用，但切片更常见

## 十四、建议你自己动手验证的练习

如果你想把这个主题真正吃透，建议在 `[arrays.go](/Users/momotom/gobyexample/examples/arrays/arrays.go)` 旁边自己试几个小实验：

1. 把 `[5]int` 改成 `[3]int`，看看哪些赋值会编译失败
2. 写一个函数接收数组参数，观察函数内修改是否会影响外部变量
3. 改成接收 `*[3]int`，再观察行为差异
4. 从数组切一个切片出来，修改切片元素，看看数组是否跟着变化
5. 用 `range` 和普通 `for` 分别遍历同一个数组，并在循环中修改元素，观察输出差异

这些实验做完，数组和切片的边界基本就很清楚了。

## 十五、总结

数组在 Go 里不是过时特性，而是一个语义很明确的基础类型：

- 它强调固定长度
- 它强调值语义
- 它适合表达结构稳定的数据

但在主流 Go 开发里，更常承担“动态序列”职责的是切片。

所以更实用的结论是：

- 学数组，是为了建立正确的数据模型意识
- 用切片，是为了完成大多数实际开发任务

把这两者区分清楚，你对 Go 集合类型的理解就已经进入进阶阶段了。
